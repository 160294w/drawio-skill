## スキルなし（ネイティブエージェント）との比較

| 機能 | ネイティブエージェント | このスキル |
|---------|-------------|------------|
| draw.io XML の生成 | はい — LLM はこの形式を理解している | はい |
| エクスポート後のセルフチェック | いいえ | はい — PNG を読み取って 6 種類の問題を自動修正 |
| 繰り返し改善のループ | いいえ — 手動で再プロンプトが必要 | はい — 的を絞った編集、5 ラウンドの安全弁つき |
| 自動起動 | いいえ — 明示的に依頼したときのみ | はい — 3 つ以上のコンポーネントがあると自動で提案 |
| レイアウトガイドライン | なし — 実行ごとに結果が変わる | 複雑度に応じた間隔、ルーティング用の通り道、ハブの配置 |
| グリッド整列 | いいえ | はい — すべての座標を 10px 単位にスナップ |
| 図表タイプのプリセット | いいえ | はい — 6 種のプリセット（ERD、UML、シーケンス、アーキテクチャ、ML/DL、フローチャート） |
| アニメーションコネクター | いいえ | はい — データフローの可視化に `flowAnimation=1` を使用 |
| ML モデル図 | いいえ | はい — テンソル形状の注釈、レイヤー種別ごとの色分け |
| カラーパレット | ランダムで一貫性なし | 7 色の意味付きシステム（青=サービス、緑=DB、紫=認証…） |
| エッジルーティングのルール | 基本的 | 入出力点の固定、接続の分散、ウェイポイントによる迂回 |
| コンテナ/グループのパターン | なし | スイムレーン、グループ、親子をネストできるカスタムコンテナ |
| エクスポートへの図表埋め込み | いいえ | はい — `--embed-diagram` でエクスポートした PNG/SVG/PDF を編集可能なまま維持 |
| ブラウザフォールバック | いいえ | はい — CLI が使えないときに diagrams.net の URL を生成 |
| デスクトップアプリの自動起動 | いいえ | はい — エクスポート後に `.drawio` ファイルを開いて微調整可能 |

## 主な利点

1. **セルフチェック + 繰り返し改善のループ** — 自身の出力を読み取り、ユーザーに見せる前に自動修正し、さらに複数ラウンドで作り込みできる、唯一の純粋 SKILL.md ソリューション
2. **6 種類の図表プリセット** — ERD、UML クラス図、シーケンス図、アーキテクチャ図、ML/深層学習、フローチャートのそれぞれに、専用の形状、スタイル、レイアウト規約が用意されている
3. **ML/DL モデル図** — テンソル形状の注釈、レイヤー種別ごとの色分け、エンコーダ/デコーダのスイムレーンなど、学術論文向けに設計
4. **マルチエージェント・ゼロ設定** — `skills/drawio-skill/` ディレクトリと draw.io デスクトップだけで 6 プラットフォーム横断で動作。MCP サーバー、Python、Node.js、ブラウザは不要
5. **プロダクション品質のレイアウト** — グリッドに沿った座標、複雑度に応じた間隔、ルーティングの通り道、ハブ中央配置戦略、アニメーションコネクター
6. **ブラウザフォールバック** — デスクトップ CLI が使えないときは diagrams.net の URL を生成。さらに編集用のデスクトップアプリも自動起動
